# 指标口径修复结果

日期：2026-09-07

## 结论

原系统把训练阶段的验证集选模指标和 checkpoint 评估指标写入同一个 `metrics_best.json`，且两处 `objective_loss` 使用不同公式。修复后，选模证据、通用评价和最终测试分别保存，评价命令不再改写选模文件。

本次没有重新训练模型。22 个本地 run 的旧 `metrics_best.json` 已先备份为 `metrics_best.pre_schema_v2.json`，再从最佳 checkpoint 恢复新版验证选模记录。17 个与注册配置匹配的实验汇总已重建。E0013 注册运行的 checkpoint 不在本机，因此没有猜测其选模值。

## 发现并修复的问题

| 问题 | 原行为 | 修复后 |
|---|---|---|
| 同名目标公式不同 | 训练用完整 `CompositeLoss`；评估写死 edge＋difference | 训练和可重放评估共用 `CompositeLoss` 构造；原局部指标改名 `edge_difference_score` |
| 评估覆盖选模证据 | `evaluate-run` 用评估 aggregate 覆盖 `metrics_best.json` | `metrics_best.json` 只由训练或解析基线验证产生；评估只写 `evaluation_<split>.json` |
| 解析基线同样覆盖 | analytic 评价函数直接写 `metrics_best.json` | run 创建时显式生成 `kind=selection, split=val` 的选模记录，后续评价不改写 |
| 可视化显示错误值 | 摘要卡优先取 evaluation 中的同名指标 | 摘要卡只显示经过校验的 validation selection 值；通用指标继续从 evaluation 读取 |
| PCA-Ridge 指标错标 | 无论配置的 primary metric 是什么，都把残差相关写到该名称下 | 计算完整验证指标后按真实 primary metric 取值，并保存完整定义 |
| 汇总混入错误配置 | 只按 E 编号收集 run，不核对配置哈希 | run 的 `config_sha256` 必须与注册表一致，否则拒绝汇总 |
| 汇总丢失历史运行 | 本机缺少的旧 RUNNING/FAILED 记录会从 summary 消失 | 保留既有历史运行；若缺少已完成运行则拒绝重建，避免静默丢证据 |
| 汇总改写人工结论 | 再次 summarize 会把 KEEP 等状态改回 AWAITING_CONCLUSION | 已有人工结论状态保持不变 |
| `metrics_last` 来源模糊 | 没有 kind、split 和定义 | 新运行写入 `kind=last_validation`、`split=val`、epoch 基准和目标定义 |
| K>1 persistence 基线 | 直接广播二维 warmup，形状不成立 | 明确使用最后一个 warmup FC 作为持续基线 |

## 历史结果恢复

动态压力实验 E0018—E0024 的验证选模目标已从 checkpoint 恢复：

| 实验 | 恢复后的 selection objective | 原汇总中的评估公式值 |
|---|---:|---:|
| E0018 | 0.01274560 | 2.46818870 |
| E0019 | 0.01589635 | 2.53037637 |
| E0020 | 0.00946956 | 2.15239074 |
| E0021 | 0.00751975 | 2.27750644 |
| E0022 | 0.01358896 | 2.12401563 |
| E0023 | 0.02925834 | 2.01106869 |
| E0024 | 0.01481201 | 2.30797902 |

这些 selection objective 只用于确认各自训练中选择了哪个 checkpoint。损失权重或损失组成不同的实验不能按该数值直接横向排名；MSE、动态校准、个体检索和 FCD 应从 `evaluation_val.json` 的独立字段比较。

E0013 的注册记录对应 `E0013-s42-20260826T123518Z-9331a35`，但本机只有配置哈希不同的 `E0013-s42-20260831T024715Z-28e891f`。旧汇总值 0.1851994312 来自已确认有问题的评估公式。注册表已将 E0013 的 primary mean 留空，summary 保留旧值为 `legacy_reported_value` 供审计。要恢复真正的 selection objective，需要取回注册运行的 checkpoint；本机后一个 run 应注册为独立实验后再汇总。

E0014—E0017 在本机有 run，但不在当前实验注册表中，因此只迁移 run 内选模记录，没有加入正式汇总。E0001—E0002 的本地 run 目录不存在，原有解析基线汇总保持不变。

## 新文件约定

`metrics_best.json` 现在包含：

- `schema_version: 2`
- `kind: selection`
- `split: val`
- `primary_metric` 和完整 `metrics`
- 零基 `best_epoch` 与 `epoch_index_base`
- `metric_definition`，包括损失类型、权重、non-overlap 起点和 batch 聚合协议

`evaluation_val.json` 和 `evaluation_test.json` 保存通用评价。可重放的新 checkpoint 会额外计算与训练配置一致的完整 objective；旧 checkpoint 如果没有记录足够的损失定义，报告明确标为 unavailable，并引用 checkpoint 中保存的历史 selection 指标。

## 验证

完整测试结果：`81 passed`。新增测试覆盖：

- MSE、Huber、variance、residual correlation、contrastive、FCD 和 PSD 组合；
- 最后一个不足 batch 的样本加权；
- 训练验证与评估重算 objective 一致；
- val/test、sequence/analytic 评价均不能覆盖选模文件；
- 可视化使用 selection 值；
- 错误 schema、split、类型、primary metric 和 NaN 会被拒绝；
- 注册配置与 run 配置哈希不一致时拒绝汇总。

迁移脚本：`scripts/repair_metric_records.py`。默认仅预览；`--apply` 才会备份并迁移。本机已执行一次，重复预览显示所有 22 个 run 均为 `already_v2`。
